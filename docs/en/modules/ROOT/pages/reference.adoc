= Reference
:description: Maven artefacts, Java modules, supported annotations, configuration.

[.lead]
Factual reference: published Maven artefacts, exported Java modules, supported Jakarta REST 4.0 annotations, configuration properties.

== Maven artefacts

[cols="2,3"]
|===
| Artefact | Role

| `io.vidocq.cassini:cassini-api:{project-version}`
| Public SPI: HTTP/transport (`CassiniHttpExchange`, `CassiniHttpAdapter`, `CassiniStack`), `BeanProvider`, `ResourceFactory`, and the codegen SPI (`ResourceAdapter`, `RouteProvider`, `RouteDescriptor`, `InjectionSupport`).

| `io.vidocq.cassini:cassini-core:{project-version}`
| JAX-RS engine (Invoker, ResourceScanner, RouteRegistry, MessageBodyRegistry, filters, providers, SSE, multipart) + the adapter generators (`RuntimeAdapterGenerator`, `AdapterRegistry`).

| `io.vidocq.cassini:cassini-client:{project-version}`
| JAX-RS Client 4.0 — zero-dependency `ClientBuilder` on `java.net.http` + virtual threads. Reuses `MessageBodyRegistry` from `cassini-core`.

| `io.vidocq.cassini:cassini-cdi-vauban:{project-version}`
| `BeanProvider` adapter that resolves resources through xref:vauban::index.adoc[Vauban] (BCE `CassiniScopeExtension` included).

| `io.vidocq.cassini:cassini-chappe:{project-version}`
| Reference transport — wires Cassini onto xref:chappe::index.adoc[Chappe] (HTTP/1.1, H2, virtual threads). Used for the TCK.

| `io.vidocq.cassini:cassini-jdk-http:{project-version}`
| Pure JDK transport — `com.sun.net.httpserver.HttpServer`, no external dependency.

| `io.vidocq.cassini:cassini-processor:{project-version}`
| APT annotation processor — generates `+$$CassiniAdapter+` / `+$$CassiniRoutes+` *sources* at compile time. AOT-safe.

| `io.vidocq.cassini:cassini-maven-plugin:{project-version}`
| Maven plugin (`generate` goal, bound to `process-classes`) — pre-generates adapters for external dependency archives.

| `io.vidocq.cassini:cassini-examples-*`
| Examples: `cassini-examples-chappe` (standard SE-Bootstrap), `cassini-examples-jdkhttp` (direct CassiniStack), `cassini-examples-vauban` (CDI + SE-Bootstrap).
|===

NOTE: `cassini-tck` is not published; it is an **in-reactor module gated behind the `tck` Maven profile** — a plain `mvn install` neither downloads nor runs anything TCK-related. See xref:tck.adoc#runner-out-of-reactor[TCK — runner architecture].

NOTE: `cassini-core` deliberately does **not** expose its `CassiniRuntimeDelegate` via `ServiceLoader` — to avoid a collision with the `RuntimeDelegate` from the active transport (`cassini-chappe` or `cassini-jdk-http`).

== Supported annotations

`@Path`, `@GET`, `@POST`, `@PUT`, `@DELETE`, `@PATCH`, `@HEAD`, `@OPTIONS`, `@HttpMethod`, `@ApplicationPath`,
`@Produces`, `@Consumes`,
`@PathParam`, `@QueryParam`, `@HeaderParam`, `@CookieParam`, `@FormParam`, `@MatrixParam`, `@BeanParam`,
`@DefaultValue`, `@Encoded`,
`@Provider`, `@Priority`, `@NameBinding`, `@PreMatching`,
`@Context`,
`@Suspended` (async — supported; SSE real-time streaming since M2i, and M2h was dropped as a non-goal — see xref:tck.adoc[TCK]).

CDI (with `cassini-cdi-vauban`): `@ApplicationScoped`, `@RequestScoped`, `@Singleton`, `@Inject`.

== Implemented JAX-RS interfaces

`Application`, `SeBootstrap`, `Configuration`, `Configurable`,
`UriInfo`, `Request`, `HttpHeaders`, `SecurityContext`, `Providers`,
`MessageBodyReader`, `MessageBodyWriter`, `ContextResolver`, `ExceptionMapper`,
`ContainerRequestFilter`, `ContainerResponseFilter`, `ReaderInterceptor`, `WriterInterceptor`,
`DynamicFeature`, `Feature`,
`Sse`, `SseEventSink`, `SseBroadcaster`,
`AsyncResponse`, `CompletionCallback`, `ConnectionCallback`,
`EntityPart`, `EntityPart.Builder` (multipart §3.5.4).

Client side (`cassini-client`): `Client`, `ClientBuilder`, `WebTarget`, `Invocation`, `Invocation.Builder`, `AsyncInvoker`, `ClientRequestContext`, `ClientResponseContext`, `ClientRequestFilter`, `ClientResponseFilter`.

== Configuration

Cassini is configured via `SeBootstrap.Configuration` (standard) or via the `CassiniStack.builder()` builder (advanced):

[cols="2,1,3"]
|===
| Property | Default | Description
| `host` | `0.0.0.0` | Transport listening interface.
| `port` | `0` (auto) | HTTP port. `0` = random free.
| `rootPath` | `/` | Mount prefix for the `Application`.
| `protocol` | `HTTP` | `HTTP` or `HTTPS` (depending on transport support).
|===

When Cassini is driven by xref:vidocq::index.adoc[Vidocq Runtime] (the `io.vidocq.runtime.extensions.jakartaee.core:vidocq-runtime-cassini-rest-extension` extension), the JAX-RS application is mounted on the shared Chappe server through the runtime's HTTP mount configuration:

[cols="2,1,3"]
|===
| Property | Example | Description
| `vidocq.http.mount.<name>.path` | `/api` | Mount prefix of the JAX-RS application in the Vidocq server.
| `vidocq.http.mount.<name>.type` | `restful` | Mount type — `restful` routes the mount to Cassini.
|===
