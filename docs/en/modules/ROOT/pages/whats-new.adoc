= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* xref:usage.adoc#unmapped-exceptions[An unmapped exception answers a bare `500`] [.tag-new]#NEW# — an exception or an error that no `ExceptionMapper` handles answers `500` with an empty body; its message, which may carry SQL text or request values, stays in the `ERROR` log with the stack trace instead of going to the client (CASSINI-046).
* xref:usage.adoc#locator-exceptions[A sub-resource locator's exception reaches the mappers] [.tag-new]#NEW# — an exception that a sub-resource locator throws goes through the application's `ExceptionMapper`s, as one from a resource method does; it skipped them and answered `500` unless it was a `WebApplicationException` (CASSINI-047).
* xref:reference.adoc#free-port[`SeBootstrap` binds a free port itself] [.tag-new]#NEW# — with `FREE_PORT` or no port, the server binds a free port of `127.0.0.1` and the instance's configuration reports it; the port was picked first and bound once the application was built, so another process could take it in between (CASSINI-049).
* xref:usage.adoc#locator-filters[Filters run on the sub-resources of a locator that returns `Object`] [.tag-new]#NEW# — the request and response filters, global or name-bound, run on a resource method reached through a sub-resource locator that returns `Object`, and the global response filters on the mapped failure of such a locator; none ran (CASSINI-050).
* xref:usage.adoc#locator-filters[The post-matching filters run after the sub-resource locators] [.tag-new]#NEW# — with a locator that returns a typed sub-resource, the post-matching request filters ran before the locators, and the response to a failing locator went through the filters bound to the method it would have led to; the locators now run first, as with a locator that returns `Object`, and only the global response filters process their failure (CASSINI-051).
* xref:usage.adoc#locator-filters[A `DynamicFeature` runs once for each resource method a locator leads to] [.tag-new]#NEW# — the features also run for the methods of a class a locator returns as `Object`, at the first request that reaches one; a method several typed locators lead to is configured once, where its filters were bound, and ran, once per locator; and a locator returning `Object` is no longer handed to the features as a resource method of `Object` (CASSINI-052).
* xref:usage.adoc#unmatched-filters[The global response filters run on a `404`, `405`, `415` or `406`] [.tag-new]#NEW# — a request the matching rejects gets its answer through the global response filters, mapped or not, so CORS or security headers reach these answers too; no response filter ran on them (CASSINI-053).
* xref:usage.adoc#unmatched-filters[A response filter's `@Context` fields follow the request it filters] [.tag-new]#NEW# — on a response with no matched resource method (a pre-matching abort, a rejected request, a locator's failure), a filter's injected `HttpHeaders`, `UriInfo` and `ResourceInfo` describe that request, with no resource method; they described the last matched request the filter had seen (CASSINI-054).
* xref:usage.adoc#locator-classes[A locator that returns `Object` reads the returned class as a typed one does] [.tag-new]#NEW# — the `@Path` of the class an `Object` locator returns is ignored, and its class `@Produces` and `@Consumes` apply to its methods; the class `@Path` was added to the sub-resource's path, and the class media types were ignored (CASSINI-055).
* xref:usage.adoc#filter-changes[The resource method gets the request as the request filters left it] [.tag-new]#NEW# — headers, entity, security context, and the method and URI a pre-matching filter sets reach the resource method's parameters and contexts, and a post-matching filter may call `setEntityStream` and `setSecurityContext`; the resource method got the request the client sent, and those two calls failed with a `500` (CASSINI-056).
* xref:usage.adoc#argument-failures[The response filters run when the arguments of a resource method fail] [.tag-new]#NEW# — the answer to a parameter that does not convert or an entity that does not read goes through the global response filters and those bound to the method; none ran on a parameter's failure, nor on an entity's unless the application had a pre-matching filter (CASSINI-057).
* xref:usage.adoc#automatic-options[The global response filters run on the automatic `OPTIONS` answer] [.tag-new]#NEW# — the `200` with an `Allow` header that answers an `OPTIONS` request to a resource with no `@OPTIONS` method goes through the global response filters, so a CORS filter adds its headers to a preflight request's answer; no response filter ran on it (CASSINI-058).
* xref:usage.adoc#filter-changes[A pre-matching filter can move the application under a new base URI] [.tag-new]#NEW# — after `setRequestUri(URI, URI)`, the request is matched on its path relative to the new base, and `UriInfo.getBaseUri()`, `getPath()`, `resolve()` and a relative `Location` follow that base; the request was matched relative to the context path of the transport, and the base URI stayed the one the client sent (CASSINI-059).
